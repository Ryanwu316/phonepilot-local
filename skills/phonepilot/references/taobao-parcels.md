# 淘宝查包裹

这是 AI 操作者的任务流程；控制台不自带模型，也不会因为复制指令而自动执行。

## 进入与范围

- 先确认服务在线、demo=false、原设备连接成功、画面新鲜。检查暂停状态，不能绕过用户暂停。
- 默认查看“待收货”全部订单。用户指定商品、日期或范围时优先采用；无法判断范围时具体询问，同时先查看不依赖答案的订单概览。
- 通过 App 列表或当前手机画面找到淘宝，打开“我的淘宝 → 待收货”。页面位置可能改变，必须按最新画面定位，不保存固定坐标。
- 登录、验证码或锁屏由用户在手机上完成。只查询，不确认收货、不付款、不下单、不申请退款、不联系商家。

## 逐单核对

1. 浏览订单列表，建立本次对话内的待查清单，区分广告、推荐商品和真实订单。记录已处理与未处理项，避免滚动后重复或遗漏。
2. 逐单打开“查看物流”。若提示多个包裹、拆单或分批发货，分别检查每一个包裹；商品数、订单数和包裹数不能混用。
3. 读取最新一条实际物流节点及其时间，必要时展开轨迹。分别记录“已发货但未揽收”“运输中”“派送中”“已签收”等，不用预计送达时间推定已经送达。
4. 出现异常、长时间无更新或只有商家发货标记时，按页面事实描述；时区和年份不明确时保留原显示并说明。不要编造签收时间、快递公司或物流节点。
5. 回到待收货列表，继续未查订单，滚动到列表结束；对照订单数量与已核对清单。页面仍显示“待收货”但物流已签收时，分别报告，不点击确认收货。

## 中断后继续

- 连接恢复期间停止操作；等原设备的新画面出现，再识别当前 App 和页面，不重复发送上一条未确认的点击或输入。
- 保留本次对话内“哪些订单、哪些子包裹已核对”的简短检查点。返回列表确认后从未完成项继续；无法恢复的项明确标为待确认。
- 若自动恢复已停止，只做一次与故障相关的人工恢复尝试；需要手动解锁、插线、信任或配对时具体请求用户处理。

## 结果与验收

输出表格：商品简称 / 包裹序号（如有拆包） / 最新实际状态与节点时间 / 异常或待确认事项。

说明查询时间、订单数与包裹数，以及是否已查到列表末尾。无法查全时报告实际已查范围，不能说“全部正常”。不复制完整订单号、运单号、地址、手机号或账号信息；不主动保存手机截图。用户明确要求保留证据时，放在本地私有位置，不能放入项目源码或发布包。

验收必须包括：至少一张当前物流页面的观察、返回订单列表后的覆盖核对、恢复后新画面与至少一次实际读取。没有真实断线事件时，只能标“模拟故障测试通过”，不能声称 USB 拔插恢复已验证。
